## 3대 원칙을 지킨 방법

1. **크게 확대하지 않기 (확대 최대 1.10배)**
   - 폰 틀 안에 앱 화면 전체(390×844 비율, 560×1212px)를 **처음부터 끝까지** 보여 줍니다.
   - 버튼을 누르는 순간에만 1.00배에서 1.10배로 살짝 다가갑니다. 이때도 폰 전체가 화면 밖으로 나가지 않도록 위치를 보정합니다(`camAt()`, `MAXZ = 1.10`).
   - 녹화할 때 기록한 최대 확대 배율은 3편 모두 `maxZoom: 1.1`입니다(`cuesheet_*.json`). 기존 숏츠의 2~2.8배 확대는 없앴습니다.
   - 끝맺음 문구(autooneclick.com)는 폰 화면을 가리지 않도록 위쪽 자막 자리에 나옵니다.
2. **실제로 누르는 버튼 표시**
   - 버튼 위치는 캡처할 때 실제 DOM에서 `getBoundingClientRect()`로 잰 값입니다(`frames/*/rects.json`).
   - 버튼 위치에 **주황(#FF6B00) 원**, **흰 손가락 포인터**(오른쪽 아래에서 다가와 눌림), **터치 파문** 2겹을 그립니다.
   - 결과·로딩 화면은 해당 영역을 **주황 둥근 테두리**로 강조합니다.
3. **나레이션과 화면을 1:1로 맞추기**
   - 나레이션은 큐마다 WAV 파일로 따로 만듭니다(`audio/*.wav`). 컷 경계는 **각 WAV의 실제 길이**로 정합니다(큐 사이 간격 0.12초).
   - 버튼 이름 바로 앞에 SSML 북마크 `<mark name="tap"/>`를 넣었습니다. SAPI가 알려 준 북마크 시각에 0.25초를 더한 순간에 손가락이 누릅니다. 버튼 이름을 말하기 시작한 직후입니다.
   - 누른 뒤 최소 0.45초는 같은 화면을 유지합니다. 그다음 결과 화면으로 바뀝니다(컷 전환 60ms).
   - 화면 그리기는 모두 오디오 시계(`AudioContext.currentTime`)로 움직입니다. 그래서 소리와 화면이 어긋나지 않습니다.
   - 위쪽 자막은 지금 들리는 문장 그대로 나옵니다. 누르는 버튼 이름은 주황색으로 표시합니다.

- 3편 모두 크롬에서 다시 열어 길이·해상도·소리를 확인했습니다.
  - 길이 25.91초 / 25.16초 / 23.06초, 해상도 1080×1920, 오디오 트랙 1개(소리 데이터가 실제로 풀림).
- 각 탭 시각(+0.25초)의 장면을 뽑아 눈으로 확인했습니다(`verify/tap_*.png`). 손가락과 주황 원이 나레이션에서 말하는 바로 그 버튼 위에 있고, 위쪽 자막도 같은 문장입니다.

## 다시 만들기 (python·node·ffmpeg 없이 PowerShell과 크롬만 사용)
```
cd src
powershell -ExecutionPolicy Bypass -File capture.ps1 -steps steps_converter.json -outDir ..\frames\converter   # viewer, saycap도 같은 방식
powershell -ExecutionPolicy Bypass -File tts.ps1 -rate 2                 # cues.json → audio/*.wav + timing.json (북마크 시각)
powershell -ExecutionPolicy Bypass -File build_data.ps1 -short converter # 화면·좌표·음성을 data_converter.js로 묶기
powershell -ExecutionPolicy Bypass -File record.ps1 -short converter     # 헤드리스 크롬 MediaRecorder로 실시간 녹화 → mp4
powershell -ExecutionPolicy Bypass -File verify.ps1 -file short_converter_model_9x16.mp4 -times "7.49,13.55" -outPrefix ..\verify\x
```
- `src/player.html?s=converter`를 크롬에서 열면 미리보기([▶ 재생])를 할 수 있습니다. [● 녹화]를 누르면 mp4를 내려받습니다.
- `src/cdp.ps1`은 PowerShell용 크롬 DevTools 연결 도우미입니다.

## 한계
- 나레이션은 Windows 기본 TTS(Heami)라 사람 목소리보다 기계적으로 들립니다. 성우나 고품질 TTS로 바꾸려면 `audio/*.wav`만 교체하고 `tts.ps1`의 북마크 시각을 다시 재면 됩니다.
- 안내 캐릭터는 실사 AI 모델이 아니라 간단한 일러스트입니다. 원본 모델 이미지는 찾지 못했습니다.
- 앱 화면은 상태별 정지 캡처입니다. 화면 안의 애니메이션(로딩 바 움직임 등)은 영상에 나오지 않습니다.
- 변환기는 사진 인식 대신 "표 붙여넣기" 흐름을 보여 줍니다. 사진 인식은 외부 AI 열쇠나 네트워크가 필요해서, 오프라인에서 결과를 그대로 재현할 수 없기 때문입니다.
- 로딩 화면 2장(변환기 "한글 문서를 만드는 중…", 더뷰 "파일을 여는 중…")은 실제 앱의 로딩 함수(`busy()`, `loader()`)를 직접 불러 띄운 화면입니다. 실제 처리는 0.1초 안에 끝나 캡처되지 않기 때문입니다.
- 세이캡 화면은 다른 작업자가 `saycap/index.html`을 고치는 중에 캡처했습니다. 그래서 뷰어 위쪽에 공유·수정·내 폰 사진 버튼이 있는 최신 상태가 담겼습니다.
